# Reliability Ladder

The measured technique-selection table for the decision loop's THINK step
(uplift 0.1). Two parts: what UAP's own paired benchmark suites measured
(generated — see below), and the selection guidance derived from those
numbers plus the external priors we have not yet reproduced locally.

## Selection guidance (THINK step)

| Task shape | Technique | Why (evidence) |
| --- | --- | --- |
| Small, well-specified, 1–2 files | **Direct** — just do it | Measured (uplift/other tiers — the medium runs predate token accounting): ~3.3–5.4k tokens/task; the e3b power run measured the full loop at +0.98 tool calls/task (significant) with correctness not separable. External prior: reflect loops cost +1–3k tokens for nothing on tasks already inside the model's competence. |
| Multi-file or gate-covered, moderate risk | **Direct + verify loop** (default UAP flow) | Measured: hard tier +2.3pt success at +22% tokens; uplift tier +4.4pt at equal tokens — both ⚠ underpowered, so directional. Gating is cheap insurance here. |
| Hardest tier, novel/ambiguous, many files | **Full loop + escalation** (convergence, gates, judge) | Measured: brutal tier 26.1% → 56.8% success (2.2×) at 4.2× tokens; the lazy variant reached 67.5% at 2.8× tokens (⚠ underpowered — directional). This is the only tier where the observed payoff dwarfs the observed cost. |
| Spec-heavy, human-available, production-critical | **SDD + human review** | External prior (context-engineering-kit, not yet reproduced locally): 95–99% accuracy at 5–35× token cost. Use when a miss costs more than 30× the tokens. |

Rules of thumb the table encodes:

1. **Escalate with difficulty, not with anxiety.** The brutal tier is the only
   one where the expensive loop's observed payoff dwarfs its cost; below it,
   spend the tokens on doing, not on judging.
2. **Token cost of a technique is part of the technique.** The lazy variant
   beat the full loop on brutal tasks at 2/3 the cost — more machinery is not
   more reliability.
3. **Cite the measurement class.** Rows not marked "usable" support cost
   claims, not quality claims — never quote a success delta without its
   discrimination status ("underpowered" = measured but inconclusive;
   "unknown" = legacy run without a discrimination block).

## Reproducing

```bash
npm run bench:ladder          # prints the table below (reads benchmark-results/)
npm run bench:ladder -- --write   # refreshes the generated block in this file
npm run bench:ladder -- --json    # machine-readable rows
```

New paired runs land in `benchmark-results/<run>/{report.json,records.jsonl}`
and are picked up on the next regeneration. The script works from worktrees
(it falls back to the main checkout's git-ignored `benchmark-results/`).

## External priors (attributed, unverified locally)

From NeoLabHQ/context-engineering-kit's published ladder: reflect +1–3k
tokens; do-and-judge 1.5–3×; SDD+human 95–99% at 5–35×. These guide the
rows UAP has not measured yet; when a local suite reproduces or contradicts
one, this section loses the row.
